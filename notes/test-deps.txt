This file enumerates all the exports of the library in a way that also details their respective dependencies.
This will allow one to choose the order of testing. 
The things with NO dependencies will be tested first. 
When no such things remain, one shall move on to the next "dependency-minimum", until all things are tested 
[either via Unit Tests, or via Demos]. 

[-2] One shall only list the concrete classes or those abstract that need be tested via extension. 

[-1] The `global.Config` object DOES NOT get to be tested, for it affects the behaviour 
of the entirety of the library. Instead, it shall be tested TOGETHER with the pieces 
that it is intended to test. 

[0] Items NOT listed here are deemed internal details that are changeable and are NOT to be tested.

[1] the abstract classes with default methods ALSO get to be tested. 
	In particular, one creates an ABSTRACT test-suite that gets to be employed for ALL 
	the child classes. 

[2] The assertions must ALL be tested (that can be), by using the specialized try-catch tests (contract testing)
